# API Documentation

Base URL: `http://localhost:8000/api/v1` (interactive docs at `http://localhost:8000/docs`).

There is **no authentication**: every request acts as a single local user.

Errors use one shape: `{"success": false, "message": "...", "detail": {...}}`.

## Health

| Method | Endpoint  | Description |
| ------ | --------- | ----------- |
| GET    | `/health` | API + database connectivity check |
| GET    | `/system-info` | Models and stack in use (LLM, embeddings, classifier) |

## Plants

| Method | Endpoint          | Description |
| ------ | ----------------- | ----------- |
| GET    | `/plants/`        | List plants (`skip`, `limit`) |
| GET    | `/plants/search`  | Search by common/scientific name (`q`, `skip`, `limit`) |
| GET    | `/plants/{id}`    | Get one plant (404 if missing) |
| POST   | `/plants/`        | Create a plant (409 if the scientific name exists) |
| PUT    | `/plants/{id}`    | Partial update |
| DELETE | `/plants/{id}`    | Delete (204) |

## Detection

| Method | Endpoint          | Description |
| ------ | ----------------- | ----------- |
| POST   | `/detect/`        | Multipart upload, field `image` (JPEG/PNG/WebP/BMP/TIFF). Returns the top match, confidence and top-5 predictions. |
| GET    | `/detect/history` | Past detections (`skip`, `limit`) |
| GET    | `/detect/{id}`    | One detection |

`plant_id` links a prediction to a plant in the database; it is `null` (and the UI shows
"No Monograph Available") when the predicted plant has no database entry.

## Chat (RAG)

| Method | Endpoint                | Description |
| ------ | ----------------------- | ----------- |
| POST   | `/chat/`                | Ask a question. Body: `message`, optional `session_id` (new session if omitted), optional `temperature` (0-1.2) and `max_tokens` (128-4096). |
| GET    | `/chat/sessions`        | List chat sessions with message counts |
| GET    | `/chat/sessions/{id}`   | Messages of one session |

Answers are generated by the local Ollama model from retrieved plant text and include
`sources` (document, chunk index, relevance score, snippet). Governance rules from the
Control Tower (toxicity guardrail, PII masking, dosage disclaimer, source verification)
are applied to every exchange.

## Control Tower

| Method | Endpoint                    | Description |
| ------ | --------------------------- | ----------- |
| GET/POST | `/control-tower/settings` | Read / update governance settings |
| GET    | `/control-tower/stats`      | CPU/RAM, session + query counts, real service health probes (SQLite, Ollama, FAISS), recent latency and token history |
| GET    | `/control-tower/audit`      | Recent compliance audit log entries |

## CMDB (ServiceNow)

| Method | Endpoint           | Description |
| ------ | ------------------ | ----------- |
| GET    | `/cmdb/connection` | Test the ServiceNow connection |
| GET    | `/cmdb/status`     | Status of the synced configuration items |
| POST   | `/cmdb/sync`       | Create/update the MediPlant CIs in ServiceNow |

Requires `SERVICENOW_INSTANCE`, `SERVICENOW_USERNAME` and `SERVICENOW_PASSWORD` in `backend/.env`.
